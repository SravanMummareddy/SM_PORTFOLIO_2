# Design System

## Purpose

Create a premium engineering portfolio that feels like a high-end technology product.

The design should communicate:

- technical depth
- precision
- maturity
- architectural thinking
- product taste

This is not a traditional developer portfolio.

---

# Design Philosophy

Inspired by:

- Apple cinematic product storytelling
- Stripe infrastructure clarity
- Linear minimal product interfaces
- Vercel developer experience
- premium engineering tools

The site should feel like:

"An operating system for an engineer's work."

---

# Primary Theme

Dark mode first.

Dark mode is the primary designed experience.

Light mode may come later.

---

# Visual Keywords

Use:

- premium
- cinematic
- quiet luxury
- architectural
- minimal
- technical
- futuristic
- elegant

Avoid:

- cyberpunk
- gaming UI
- excessive neon
- hacker stereotypes
- template portfolio aesthetics

---

# Color Direction

Primary:

Deep blacks:

- near black backgrounds
- graphite surfaces
- layered dark panels

Secondary:

Subtle metallic tones:

- gray
- silver
- muted blue-gray

Accent:

Use very selectively.

Possible accents:

- electric blue
- soft violet
- subtle cyan

Accent colors should represent:

- intelligence
- systems
- connectivity

Never use large glowing colorful sections.

---

# Layout Philosophy

Use:

- large whitespace
- strong hierarchy
- intentional empty space
- cinematic sections
- editorial layouts

Avoid:

- dense grids everywhere
- many cards
- dashboard overload
- resume-style pages

---

# Typography

Typography should feel:

- premium
- technical
- confident

Large typography is preferred.

Hero:

- oversized
- minimal
- memorable

Body:

- readable
- calm
- professional

Avoid:

- too many font sizes
- playful fonts

---

# Components

Components should feel like parts of a system.

Examples:

Good:

- glass panels
- architecture cards
- floating system nodes
- timeline components
- terminal-inspired elements
- topology diagrams

Avoid:

- generic project cards
- colorful badges everywhere
- emoji-heavy UI

---

# Cards

Cards should:

- have depth
- subtle borders
- layered surfaces
- soft shadows
- controlled blur

Cards should NOT:

- look like Bootstrap cards
- look like GitHub README sections

---

# Project Visual Language

Projects are not cards.

Projects are systems.

Each project should have:

- visual metaphor
- architecture representation
- interaction model

Examples:

LuminTrack:

Visual:
workflow graph

KGD ERP:

Visual:
business operation flow

Enterprise systems:

Visual:
distributed architecture map

TTS:

Visual:
personal data constellation

EdgeStack:

Visual:
decision analytics system

---

# 3D Design Rules

3D should represent:

- systems
- connections
- architecture
- data movement
- intelligence

Examples:

Good:

- nodes connecting
- pipelines forming
- system layers moving
- architecture worlds

Bad:

- random floating laptop
- spinning cubes
- decorative planets
- meaningless objects

---

# Interaction Design

Interactions should feel:

like a system responding.

Examples:

Hover:

- reveal architecture details
- expose metadata
- expand system information

Scroll:

- assemble systems
- connect components
- reveal complexity

Click:

- transition deeper into system view

---

# Accessibility

Maintain:

- readable contrast
- keyboard navigation
- reduced motion support
- responsive layouts

Premium does not mean unusable.

---

# Responsive Strategy

Priority:

1. Desktop cinematic experience
2. Laptop optimization
3. Mobile adaptation

Desktop first.

Mobile should remain clean but does not need every cinematic effect.

---

# Visual Quality Test

Before accepting any section ask:

Would this belong on:

- Linear?
- Stripe?
- Vercel?
- a premium SaaS landing page?

If no:
redesign.

---

# Final Design Goal

The visitor should think:

"This person builds software with engineering depth and product taste."
