# Portfolio Projects Strategy

## Purpose

Projects should not appear as basic cards.

They should be presented as engineering case studies that show:

- architecture thinking
- backend depth
- system design
- product taste
- operational reasoning
- AI-assisted workflow thinking

The goal is to make senior engineers think:

"He is not just building apps. He understands systems."

---

# Project Hierarchy

## Tier 1 — Flagship Cinematic Case Studies

These receive the deepest storytelling, architecture diagrams, and cinematic scroll sections.

### 1. LuminTrack — Workflow Intelligence Platform

Positioning:
A workflow intelligence platform for multi-stage operational processes.

Do not present as:

- just an HR app
- just a recruitment tracker
- just CRUD

Present as:

- state-machine workflow system
- event/activity timeline
- RAG-powered document search
- role-based operational platform
- internal tools architecture

Core themes:

- strict transition state machine
- event-sourced activity timeline
- WebSocket-driven updates
- RAG search over uploaded documents
- OAuth 2.0 + JWT sessions
- PostgreSQL data modeling
- operational analytics

Visual metaphors:

- state transitions
- workflow graph
- event stream
- document embeddings
- AI retrieval layer
- timeline reconstruction

Suggested case study flow:

1. Manual workflow chaos
2. Structured operational model
3. State machine
4. Activity/event timeline
5. AI/RAG document intelligence
6. Analytics and operational visibility
7. Tradeoffs and future scale

# Project Presentation Rules

## Homepage

Homepage should show projects as cinematic previews.

Each preview should include:

- project name
- one-line positioning
- technical focus
- visual metaphor
- CTA to deep case study

Do not overload homepage with all details.

---

## Deep Case Study Pages

Each flagship case study should include:

1. Problem
2. System goal
3. Architecture
4. Data model
5. Key technical decisions
6. Tradeoffs
7. What I built
8. What I would change at 10x scale
9. Visual diagrams
10. Lessons learned

---

# Status Labels

Use elegant status labels.

Examples:

- Production Beta
- Active Build
- Case Study
- Enterprise Abstract
- Experimental System

Do not hide that some projects are evolving.

But present them confidently.

---

# What To Avoid

Avoid:

- generic project cards
- vague "built with React" descriptions
- inflated AI claims
- roadmap-only features
- fake metrics
- screenshots without explanation
- too many buzzwords

---

# Recruiter/Senior Engineer Goal

A senior engineer should see:

- state machines
- idempotency
- event timelines
- APIs
- database modeling
- tradeoffs
- scaling paths
- observability thinking
- AI integration where useful

A recruiter should see:

- polished presentation
- strong projects
- modern stack
- clear technical identity
- proof of execution
