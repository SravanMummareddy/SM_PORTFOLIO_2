# Portfolio Architecture

## Purpose

This document defines the structure of Sravan Mummareddy's engineering portfolio.

This is not a resume website.

It is an interactive engineering system showcasing:

- backend architecture
- distributed systems thinking
- operational platforms
- AI-assisted workflows
- product engineering taste

---

# Core Experience Model

The portfolio has two layers.

## Layer 1 — Cinematic Homepage

Purpose:

Create emotional impact.

Visitors should think:

"This engineer is different."

Focus:

- identity
- systems thinking
- featured engineering stories
- premium interaction

---

## Layer 2 — Deep Technical Pages

Purpose:

Create technical trust.

Senior engineers should see:

- architecture decisions
- tradeoffs
- system models
- scaling considerations

# Case Study Page Structure

Every major project follows:

---

## Opening

Include:

- system name
- positioning
- technical focus
- status

Example:

LuminTrack

Workflow Intelligence Platform

Status:
Active Build

---

## Problem

Explain:

What operational problem existed?

---

## System Overview

Visual architecture.

Show:

- frontend
- backend
- data
- integrations
- AI components

---

## Architecture Deep Dive

Include:

- diagrams
- data flows
- state machines
- APIs
- async workflows

---

## Technical Decisions

Explain why.

Examples:

Why:

- PostgreSQL
- event model
- state machine
- caching
- authentication model

---

## Tradeoffs

Show senior thinking.

Examples:

"We chose X because Y, but at larger scale Z would change."
